# 요구사항 정의서

**문서 번호** SC-01 · **버전** v1.0 (2026-10-01) · **작성** 김우주 · **관리** 손승우

## 1. 개요

### 1.1 목적

이 문서는 스킨케어 서비스가 **무엇을 해야 하는지**를 정의합니다. 구현 방법은 [시스템 설계서](02-system-design.md)와 [API 명세서](03-api-spec.md)에, 검증 방법은 [테스트 계획서](08-test-plan.md)에 있습니다. 모든 요구사항에는 ID가 있고, 이 ID로 화면·API·테스트 케이스를 추적합니다(§6).

### 1.2 서비스 한 줄 정의

사용자가 스마트폰으로 얼굴을 촬영하면 부위별 피부 상태 4개 지표(수분·탄력·색소침착·모공)를 수치로 보여주고, 그 결과와 설문을 근거로 스킨케어 성분과 관리 루틴을 추천 이유와 함께 제시한다.

### 1.3 범위

| 구분 | 내용 |
|---|---|
| 포함 | 회원 관리, 촬영·업로드, 설문, 피부 상태 측정, 피부 타입·고민 도출, 성분·루틴 추천, 결과 리포트, 측정 이력·추이 |
| **제외** | 질환 진단(여드름·아토피·피부암 등), 치료·처방·의약품 안내, 특정 제품 판매·광고, 소셜 기능, 네이티브 앱 |
| 근거 | 식약처 「의료기기와 개인용 건강관리(웰니스) 제품 판단기준」 — 질환 진단은 의료기기 영역 / 화장품법 — 효능 단정 표현 금지 |

### 1.4 사용자

| 구분 | 설명 |
|---|---|
| 일반 사용자 | 만 14세 이상, 자신의 피부 상태를 수치로 확인하고 관리 성분을 알고 싶은 사람. 모바일 브라우저로 접속 |
| 운영자(팀원) | 별도 관리자 화면은 두지 않음. 서버 로그·DB로 운영 |

### 1.5 용어

| 용어 | 정의 |
|---|---|
| ROI | 관심영역. `full_face`, `forehead`, `glabella`, `eye_left`, `eye_right`, `cheek_left`, `cheek_right`, `lip`, `chin` 9개 |
| 지표 | `moisture`(수분), `elasticity`(탄력), `pigmentation`(색소침착), `pore`(모공). 서비스 노출 값은 0–100 |
| 분석 | 이미지 1장 + 설문 1건에 대한 측정·추천 한 묶음 |
| 측정 | 이미지 → ROI별 지표 예측 (피부 상태 회귀 모델, 담당 박성근·김우주) |
| 추천 | 지표 + 설문 → 성분·루틴·근거 생성 (성분 추천 sLLM, 담당 김우주) |
| 데모 값 | 회귀 모델 연결 전 AI 서버가 돌려주는 가짜 측정값(`isDemo: true`). 실측처럼 보여주면 안 됨 |
| 폴백 | sLLM 출력이 형식을 어기면 대신 내보내는 규칙 기반 추천 |

> **MR-06 해석 주의.** 이 데이터는 고민별 추천 성분이 거의 고정되어 있어 "고민별 빈출 성분" 규칙만으로도 precision@3 68.8%가 나옵니다. 따라서 발표에서는 목표 달성 자체보다 **같은 문항 비교에서 규칙 대비 +9.7%p(95% CI ±5.1)**, **원본 모델 대비 0.9% → 78.4%**, **금칙 표현 필터 개입률 35.8% → 0.5%** 를 함께 제시합니다. 상세는 `skincare-ai/docs/ai-module.md`.

> **MR-05 (D2).** 현재 피부 타입은 설문 자가응답으로 받고, 응답이 "모름"일 때만 수분 지표로 추정합니다. 피지 지표가 없어 측정값만으로 4종 분류는 어렵습니다. ① 회귀 모델 출력 + 설문으로 분류기를 별도 학습하거나 ② 지표를 "고민 도출 일치율"(측정값 기반 고민 vs 사용자 자가 고민)로 바꾸는 것 중 하나를 정해야 합니다.
