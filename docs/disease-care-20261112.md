# 질환별 관리 조건의 최종 응답 검증

## 수정한 문제

직전 평가의 추천 응답 15개 중 질환별 관리 조건이 적용되는 11개에서 해당
문구가 누락됐다. 성분 카드의 효능·사용 조건 검사는 통과했으나,
`care_conditions`를 제품별 교정 지침과 근거 카드 대체 응답에 전달하지 않았고
최종 검사에서도 확인하지 않았다.

`disease_care.py`가 기존 근거의 관리 문구와 출처 ID를 연결한다.
근거 검색, 제품별 교정 지침, 재생성용 JSON 초안, 서버 근거 카드 대체 응답에
같은 문구를 전달한다. 최종 검사에서 필수 문구 누락과 일부 명시적 모순을
확인한다. 원래 모델 출력과 교정 시도는 별도로 보존한다.

## 적용 범위와 출처

| 분류 참고 라벨 | 조건 | 적용 대상 | 출처 |
|---|---|---|---|
| 아토피 | 세정 뒤 수분이 남아 있을 때 보습 | 선택한 보습제 | [AAD 아토피 피부 관리](https://www.aad.org/public/diseases/eczema/types/atopic-dermatitis/atopic-dermatitis-coping) |
| 건선 | 세정 뒤 수분이 남아 있을 때 보습 | 선택한 보습제 | [AAD 건선 목욕·샤워 관리](https://www.aad.org/public/diseases/psoriasis/skin-care/baths-showers) |
| 주사 | 세정 후 피부가 마른 다음 보습 | 선택한 보습제 | [AAD 주사 피부 관리](https://www.aad.org/public/diseases/rosacea/triggers/tips) |
| 지루 | 순한 세정 후 무향·알코올 없는 보습 제품 | 선택한 보습제 | [AAD 지루성 피부염 관리](https://www.aad.org/public/diseases/a-z/seborrheic-dermatitis-self-care) |
| 지루 | 알코올 없는 완제품 | 선크림을 포함해 선택한 모든 제품 | 같은 AAD 지루성 피부염 자료 |

2026-11-12에 원문을 확인했다. 건선의 기존 출처는 세정 후 보습을 설명했지만
물기가 남은 피부에 사용하는 조건의 직접 근거는 목욕·샤워 안내여서 링크를
구체화했다. 지루 자료의 알코올 회피는 보습제 외에 선크림 등에도 적용되므로
선크림만 선택한 응답에도 공통 조건을 추가했다. 성분 카드의 효능 문장은 같다.
근거 저장소는 `ingredient_evidence_20261112_v2`로 구분한다.

이는 분류 참고값에 연결한 일반적인 화장품 보조 관리 안내다. 사진에서 실제
건조함·장벽 손상·병변·중증도나 개인별 제품 적합성을 측정하지 않는다.
원료의 농도·약물·치료법·새 사용 횟수는 추가하지 않는다.

## 생성과 검사

1. 실제 예측 라벨과 회피 조건으로 허용 성분 카드를 검색한다.
2. 선택한 제품에 해당하는 관리 문구를 생성·교정 지침에 넣는다.
3. 관리 문구가 사용법 단계에 있는지 확인한다. 반대 보습 시점이나 알코올 함유
   제품 권유 등 일부 명시적 모순은 답변 다른 단계에 있어도 검출한다.
   실제 응답의 `routine`과 `reasoning`에도 문구가 남았는지 확인해 루틴 길이
   제한이나 문장 필터로 조건이 사라진 결과를 보류한다.
4. 교정이 실패하면 허용 근거 카드와 관리 문구로 구성한 응답을 다시 검증한다.
   이때 `generation_origin=source_cards`, `used_fallback=true`를 유지한다.
5. 공통 검사를 통과하지 못하면 기존 `quality_rejected`로 보류한다.

선크림만 선택한 경우 보습 시점을 요구하지 않는다. 여드름·정상에는 이 네
질환의 조건을 추가하지 않는다. 회피 성분을 근거 카드 선택으로 다시 도입하지
않는다. 검사기는 근거 문구를 그대로 보존했는지 확인하는 보수적인 문자열
검사이며 모든 모순의 의미를 판정하는 임상 검증기가 아니다.

성분별 `purpose`가 정확해도 최종 요약에서 선크림에 수분 유지·건조함 관리
효능을 함께 연결하는 문장이 나올 수 있었다. 확인된 문장 구조는
`evidence_sunscreen_moisturizer_claim_mixed`로 교정 대상으로 처리한다.
제품별 주어가 분리된 설명은 유지한다. 이 역시 제한된 문장 검사다.
화면용 문장에 섞인 근거 내부 ID는 표시에서 제거하고 원문·근거 메타데이터에
보존한다. 생성된 성분명이나 효능을 사후에 새로 작성하지 않는다.

## 검증 재현

기존 평가 결과, 원래 사진 폴더, 로컬 모델·어댑터와 GPU가 필요하다.
새 결과 폴더를 지정하며 기존 평가 파일을 덮어쓰지 않는다.

```powershell
python scripts/evaluate_disease_care.py `
  --baseline ../AI/outputs/flow_quality_20261112 `
  --assets-dir ../AI `
  --photos C:/Users/User/Downloads/test_sample_96/test_sample_96 `
  --output ../AI/outputs/disease_care_new_run
```

이 평가는 기존 20건의 저장 응답 재검사와 실제 DenseNet·Qwen 요청을 구분한다.
새 설문은 기존 사진에 적용한 가상 설문이며 새 환자 검증 자료가 아니다.
사진의 정답 라벨을 추천 입력으로 사용하지 않는다. 원본 사진은 원래 위치에서
읽으며 결과 폴더나 외부 저장소로 복사하지 않는다.

## 실측 결과

2026-11-12, RTX 5070 Ti에서 Qwen2.5-7B와 기존 v2 어댑터를 로드했다.
기존 설정대로 근거 문맥 생성 중에는 어댑터를 비활성화했다. 모델 재학습이나
분류 임계값 변경은 하지 않았다. 실제 DenseNet CPU 분류와 Qwen GPU 생성은
FastAPI TestClient를 통해 수행했다.

| 항목 | 결과 |
|---|---|
| 기존 저장 응답 재검사 | 20건 중 관리 조건이 필요한 11건의 누락을 모두 탐지 |
| 같은 입력의 기존 추천 재생성 | 6건 모두 제공, 관리 조건이 필요한 5건은 누락 5건에서 0건으로 감소 |
| 새로운 가상 설문 조합 | 민감성·복합 고민·회피·선크림 단독 4건 모두 제공, 필요한 관리 조건 4건 유지 |
| 최종 추천 제공 | 10건, 성분 설명·효능 문장·근거 연결 19개 확인 |
| 관리 조건 | 해당 9건 모두 최종 `reasoning`과 `routine`에 유지, 문구 10개 |
| 제품별 사용 조건 | 10건 모두 무향·표시 사용·자극 시 중단·해당 선크림 조건 검사 통과 |
| 회피 조건 | 실제 회피 성분을 지정한 5건 모두 해당 성분 제외 |
| 출처 | 모델 답변 4건, 근거 카드 대체 6건, 규칙 추천 제공 0건 |
| 미생성 분기 | 고민 없음·분류 불확실·전 성분 회피 각 1건에서 생성 없이 종료 |
| 잘못된 파일 | 파일 형식 불일치 415, PNG 헤더 뒤 손상된 본문 422, 추천 호출 0회 |
| 추천 요청 처리 시간 | 최종 선택한 10개 응답의 중앙값 30.35초, 최대 41.70초 |
| PR 분리 작업 트리 | 495 passed, 12 skipped |
| 원래 AI 작업 트리 | 635 passed, 4 skipped |

위 표의 14개 시나리오에 실제 요청 14회를 보냈다. 이후 요약 효능 혼동과 내부
근거 ID 표시를 보완해 2건을 실제 사진으로 다시 요청했다. 최종 결과표에는
같은 시나리오의 마지막 응답을 사용한다. 잘못된 파일의 형식 검사·본문 해석
구분을 추가로 2회 확인했다. 이 보고서에 집계한 HTTP 시험은 18회이며 추천
제공 시나리오는 중복을 제외한 10개다. 저장 출력 재검사 스크립트를 다시
실행하며 반복한 동일 파일 오류 검사는 중복 집계하지 않는다.

최초 잘못된 파일 시험은 PNG/JPEG 헤더도 없는 자료에 422를 기대한 시험
작성 오류로 중단됐다. 서버는 설계대로 415를 반환했다. 이후 두 오류 조건을
분리해 재검증했으며 원래 실패 기록과 수정 사유를 보존했다. 모델 추론 중
코드 해시가 바뀌지 않았음도 확인했다.

최종 출력 잘림 검사와 내부 근거 ID 표시 처리를 적용한 뒤 최종 10개 결과의
저장된 실제 모델 출력·교정 경로를 공통 생성/검사 코드로 재실행했다. 추가
모델 호출 없이 같은 성분·효능·관리 조건을 유지했다. 이는 저장 출력 재검사이며
새 추론 10회로 세지 않는다. 마지막 코드로 새로 추론한 2건은 별도로 기록했다.

## 원문 검토와 해석 한계

소프트웨어 에이전트가 최종 제공 문장 10건을 직접 읽었다. 개인의 병변 부위·원인·
중증도를 확정하는 표현이나 지정한 회피 성분의 재도입은 확인하지 못했다.
기존 여드름 사례의 교정 중에 나온 보습제·선크림 공동 보습 효능 요약은 새 검사로
잡혔고, 최종 응답은 제품별 근거 문장과 선택 요약으로 제공됐다. 경미한 조사
오류인 ‘글리세린와’ 1건은 남았으며 성분명·효능 오류와 구분했다.

제품 사용 조건이 원문 문장 그대로인 성분 항목은 14/19개다. 나머지는 모델이
표현을 바꾸어 제품별 검사와 원문 검토를 거쳤다. 따라서 문장 전체가 모두
근거 카드와 문자 단위로 같다고 주장하지 않는다. `purpose`와 성분명을 결합한
효능 문장은 19/19개가 카드와 일치했다.

이는 작은 회귀 시험이다. 새 설문도 기존 사진에 적용한 가상 인적 정보다.
직전 96장 분류 평가의 정확도 93.75%, Macro F1 0.9373은 이번 수정으로 새로
측정한 수치가 아니다. 이번 실제 이미지 분류에서도 해당 이미지의 예측
분포가 앞선 실행과 같았다. 예측값이 추천 입력이며 정답 라벨을 추천에 넣지
않는다. 새 환자 일반화와 성분의 임상적 효능 정확도는 측정하지 않았다.
전문가 검토를 거친 임상 품질 점수도 없다.

기존 사진과 같은 설문을 쓰면 성분 조합이 반복되는 한계도 남는다. 이 문제를
줄이기 위한 허용 성분·제품 조건 확장은 검토된 추가 근거와 평가 자료가
필요하다. 근거가 없는 성분을 임의로 늘려 다양성을 높이지 않았다.

기존 Swift·Spring 응답 필드에는 변경이 없다. 이번 신규 실측의 범위는
FastAPI와 실제 AI 모델이다. 앞선 Swift → Spring → FastAPI 시험 결과와
이번 시험 횟수를 합산하지 않는다. macOS/iOS 실제 앱 빌드는 이번에 수행하지 않았다.

## 로컬 결과 파일

사진과 응답 원문은 Git에 올리지 않는다. 로컬 결과는
`AI/outputs/disease_care_20261112`에 있다.

- `responses.jsonl`, `followup.responses.jsonl`은 실제 요청과 생성 원문·교정 기록이다.
- `replay.jsonl`은 기존 저장 응답 20건의 재검사다.
- `metrics.json`, `manual_review.json`, `report.md`는 집계와 검토 결과다.
- `final_guard_replay.json`은 최종 코드로 저장 출력을 재실행한 기록이다.
- `malformed_image_checks.json`은 두 파일 오류 경로의 추가 시험이다.
- `failure.json`, `protocol_correction.json`, `run_integrity.json`은 시험 예상값 수정과 실행 무결성 기록이다.
- `followup.done.json`, `done.json`은 새 추론과 최종 검증의 완료 상태다.
