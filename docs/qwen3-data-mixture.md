# Qwen3 비교와 외부 보조 데이터 실험

2026-10-08에 사용자 요청에 따라 별도 실험을 준비했다. 기존 v1/v2/v3와 미완료 Qwen3-v2의 데이터·어댑터는 보존한다. 서버 기본 모델은 이 실험에서 교체하지 않는다.

## 비교 설계

1. GPU 없이 데이터 무결성과 Qwen2.5/Qwen3 토큰 길이·학습 제외 ID를 검사한다.
2. 실제 Qwen3-8B의 4-bit 역전파를 길이 제한 안의 가장 긴 학습 사례 4건으로 3스텝 시험한다.
3. Qwen3 원본을 기존 v3 개발 144문항에서 평가한다.
4. Qwen3에 기존 v3만 2에폭 학습하고 같은 문항에서 평가한다.
5. Qwen3에 기존 v3와 외부 보조 사례를 섞어 학습하고 같은 문항에서 평가한다. 순수 v3 실험과 옵티마이저 업데이트 수를 맞춘다. 보조 사례가 일부 배치를 차지하므로 원본 사례의 노출 횟수는 조금 줄어든다.
6. 기존 규칙·Qwen2.5 원본·v2·v3의 검증된 결과를 재사용해 비교표와 내용 검토 파일을 만든다. 완료된 평가를 다시 돌리지 않는다.

Qwen3는 학습·추론 모두 `enable_thinking=False`를 쓴다. 모델 교체 효과를 구분하기 위해 공통 추론 조건(1차 greedy, 실패 시 temperature 0.3/top_p 0.9로 한 번 재시도, 출력 최대 2400토큰)을 유지한다. 이는 Qwen3 모델 카드가 제시한 일반적인 non-thinking 샘플링 권장값(0.7/0.8/top_k 20)을 최적화한 비교는 아니다. [Qwen3 공식 모델 카드](https://huggingface.co/Qwen/Qwen3-8B).

토크나이저에 따라 2048토큰 제한으로 제외되는 학습 사례가 달라질 수 있다. `data_profile.json`에 포함 ID 해시·제외 ID·고민별 제외 수를 저장하며, 모델만 바꾼 비교에도 이 차이가 있음을 보고한다. 독립 시험이나 전문가 효능 승인이 완료된 실험으로 표현하지 않는다.

## 외부 데이터 구성과 의미

최종 보조 파일은 `data/auxiliary_20261008_v2/train_auxiliary.jsonl`이다. 원래 추천 학습 7,564행은 변경하지 않는다. 추가한 **112행(원래 학습 건수 대비 약 1.48%)**은 다음 두 가지다. 토큰 길이 검사 후 실제 사용 수는 학습 정보에 기록한다.

| 출처 | 후보 원본 | 선택 | 학습 과제 |
|---|---:|---:|---|
| INCIDB 무료 표본 / Open Beauty Facts | 제품 200개 | 제품 32개 | 전성분 원문에서 정확한 INCI 이름 식별. 파생물·식물 부위·유사 이름을 합치지 않음 |
| CureSkin Ingredient Flags | 사전 1,448행 | 관련 성분 80개 | 제공한 사전 행을 JSON으로 정리. 빈 값은 미평가(null), 출처의 0과 구분 |

INCIDB에서 명시적인 스킨케어 범주가 아닌 167제품과 정확히 연결할 수 없는 1제품을 제외했다. 성분 이름 매핑은 원본의 `exact` 및 confidence=1.0 항목만 사용한다. 성분 이름에 들어가는 쉼표(예: 1,2-hexanediol)를 보존한다. 사전은 선택 제품에 실제 나타나는 이름 또는 프로젝트 사전과 정확히 연결되는 이름만 사용해 관련성 낮은 행을 제외했다. 행을 복제하거나 허용 건수까지 임의로 채우지 않았다.

보조 과제에는 별도 system/user 프롬프트를 쓰고 답변 토큰에만 손실을 준다. 개인 프로필·피부 고민별 추천 정답·효능 문헌을 합성하지 않는다. 제품에 성분이 표기되어 있다는 사실은 효능·농도·사용 안전성을 증명하지 않는다. 사전의 기능 표현도 해당 출처의 설명이며, 개인에게 효과가 있다는 승인된 정답이 아니다. 희소·복합 고민 정답의 부족은 이번 보강으로 해결되지 않는다. 성능 개선은 아직 검증 전이다.

### 출처와 사용 조건

- [INCIDB 무료 표본](https://huggingface.co/datasets/Ichlibitiche/incidb-skincare-free-sample): 고정 버전 `b866a0f3fa3355a360ee6f6597af717655b40acd`. 제품 원본은 Open Beauty Facts 기여자, ODbL 1.0. 무료로 공개된 부분만 사용한다. 표본은 원본 설명상 성분 연결률이 높은 제품을 먼저 골라 편향이 있다.
- [CureSkin Ingredient Flags](https://huggingface.co/datasets/cureskin/indian-skincare-ingredient-flags): 고정 버전 `e34203b35153fd1cd9de6de7c938165c722c003f`, CC BY 4.0. 빈 플래그는 미평가이며 제품 안전성으로 일반화하지 않는다.

출처·사용 조건·변경 내용·파일 해시는 `manifest.json`과 `ATTRIBUTION.md`에 보존했다. ODbL 파생 보조 데이터는 별도 파일로 관리하고 배포 시 출처·동일조건 의무를 유지한다. AI Hub 추천 원본을 이 파일에 복사하지 않았고 재배포하지 않는다. 유료 전체 스냅샷, 라이선스 없는 CosIng 사본, 원본 권리를 확인할 수 없는 설명문을 학습에 추가하지 않았다. 접근 허가가 필요한 데이터를 다른 데이터와 섞어도 그 조건이 사라지는 것은 아니다.

## 검은 화면 감시

최근 일주일 시스템 로그에서 NVIDIA `nvlddmkm` 오류 153번 73건, 13번·14번 각 3건을 확인했다. Windows 오류 보고의 `LiveKernelEvent 141`과 WATCHDOG 덤프 경로도 있었다. 10월 7일 03:18:45 드라이버 오류는 이전 v3 학습의 03:18:48 CUBLAS 실패 직전이다. 시각이 맞는 중요한 단서지만 전원·온도·드라이버·하드웨어 중 원인을 확정한 것은 아니다. Windows는 GPU가 응답하지 않으면 TDR로 복구하며 관련 로그를 남긴다. [Microsoft TDR 설명](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/timeout-detection-and-recovery).

`scripts/gpu_watchdog.py`가 각 GPU 자식 프로세스를 감시한다. 약 15초 간격으로 GPU 온도·VRAM·사용률·전력과 새 시스템 이벤트를 저장한다. 조회마다 6초 제한을 두고 다음 조건에서 **해당 자식 프로세스만 종료**하며 이후 단계를 시작하지 않는다.

- 실행 이후 새 NVIDIA 오류, 디스플레이 복구 이벤트 4101 또는 하드웨어 경고/오류.
- GPU 조회 또는 이벤트 조회가 연속 3번 실패.
- GPU 온도 85℃ 이상이 30초 지속.
- 진행 로그가 15분 동안 변하지 않음.
- 감시 실행 사이 120초 이상 공백(절전·정지 가능성 포함), 시스템 이벤트 로그 초기화 또는 사용자가 `STOP` 파일 생성.

과거 이벤트는 시작 시 기준 RecordId를 저장해 새 장애로 취급하지 않는다. 안전 중단을 자동 재시작하지 않는다. 드라이버 오류가 발견되면 해당 시점 텔레메트리와 이벤트 XML을 남긴다. 이 감시는 화면을 직접 보는 것이 아니며, Windows 전체가 멈추면 감시도 실행될 수 없다. 그 경우 마지막 기록·재부팅 시각·오류 보고로 사후 확인한다. 중단해도 마지막 체크포인트 이후의 학습은 잃을 수 있고, 이 장치가 전체 PC 멈춤을 예방한다고 보장하지 않는다.

드라이버 설치, GPU 클럭/전력, TDR 레지스트리, Windows 보안/실행 정책은 변경하지 않는다. 감시 초기화에 실패하면 GPU 작업을 시작하지 않는다.

## 실행과 확인

```powershell
# 캐시에 모델과 별도 보조 파일이 있는 기존 venv에서 실행
.\.venv\Scripts\python.exe scripts/run_qwen3_comparison.py
# 실패 뒤 동일 실험 재개는 원인 확인 후에만; 안전 중단/비정상 종료는 자동 재개 거부
.\.venv\Scripts\python.exe scripts/run_qwen3_comparison.py --resume
```

상태·로그 경로: `outputs/qwen3_comparison_20261008_02/`. `status.json`은 단계별 결과, `watchdog.json`은 현재 GPU 자식과 최신 감시, `gpu_telemetry.jsonl`은 시계열, `safety_events.jsonl`은 중단 근거다. 같은 폴더에 `STOP` 파일을 만들면 다음 감시에서 실험을 중단한다. 최종 어댑터는 `outputs/rec_sllm_v3_qwen3_bf16/adapter`, 보강 어댑터는 `outputs/rec_sllm_v3_qwen3_mix_bf16/adapter`에 별도로 저장한다.

### 초기 긴 시퀀스 시험과 메모리 조정

최초 시험은 첫 역전파에서 bitsandbytes 메모리 부족으로 종료됐다. 새 시스템 드라이버 오류는 없었고 다음 GPU 단계는 실행되지 않았다. 실패 로그는 `outputs/qwen3_comparison_20261008/`에 보존했다.

현재 설정은 4-bit 준비 과정에서 FP32로 변환되는 동결 입력 임베딩·출력층만 원래 로딩 정밀도인 BF16으로 저장한다. LayerNorm은 FP32로 유지하며 LoRA 업데이트는 기존 방식대로 학습한다. 길이 제한을 낮추거나 JSON 정답을 자르지 않는다. 메모리 정책·예상 절약량·최대 PyTorch 할당/예약량을 학습 정보에 기록한다. 두 Qwen3 학습 실험에 같은 정책을 적용한다. 기존 Qwen2.5와 비교할 때 이 메모리 설정 차이를 함께 명시하며 장기 안정성을 짧은 시험으로 보장하지 않는다.

Windows venv 실행기는 실제 CUDA Python을 별도 자식으로 시작한다. 종료 시 실행기뿐 아니라 생성 시각으로 식별한 해당 자식 트리까지 정리한다. 테스트에서도 실제 Python이 종료되고 별도 프로세스는 살아 있음을 확인한다.

### 2026-10-08 본학습 중 GPU 리셋 감지

원본 Qwen3 개발 144문항 평가는 03:43:56 종료 코드 0으로 완료됐으며 결과 파일의 문항·채점 기준·데이터 ID를 다시 검증했다. 본학습은 마지막 완료 표시 **16/940스텝**에서 `torch.AcceleratorError: CUDA error: unknown error`로 종료됐다. 04:02:09부터 NVIDIA 이벤트 원문에 `Graphics FECS Exception: UCODE Fatal Error`, `GPU Reset Required`, TDR 리셋·재시작이 연이어 기록됐다. 같은 시점 GPU 조회도 6초 제한을 넘겼다. 감시기는 04:02:37 `safety_stopped`를 기록했고 후속 학습·평가를 시작하지 않았다.

학습 중 측정된 GPU 최고 온도는 57℃, VRAM 최고 사용량은 15,960MiB, 최소 잔여량은 36MiB였다. 메모리 여유가 매우 적었다는 관측이며 드라이버 리셋의 최종 원인을 증명하지는 않는다. GPU 응답 정지와 드라이버 복구가 실제로 있었지만 화면 자체를 관찰한 기록은 없다. 복구 후 GPU 조회가 정상이고 학습·실행기 프로세스가 모두 종료됐음을 확인했다. 재부팅 시각은 이전과 같았다.

`outputs/rec_sllm_v3_qwen3_bf16/checkpoint-10`에 어댑터·옵티마이저·스케줄러·RNG·학습 상태 파일이 남아 있다. 기존 데이터와 모든 완료 평가를 보존했으며 자동 재시작하지 않았다. 원인 요약은 현재 run의 `gpu_incident_summary.json`, 원문은 `safety_events.jsonl`, 시계열은 `gpu_telemetry.jsonl`에 있다. GPU 장애 시 모니터를 일시 중지하라는 기존 지시에 따라 시간당 모니터도 PAUSED로 변경했다.

전체 개발 비교와 보강 학습은 미완료다. 중단 전 완료 예상 시간은 더 이상 적용할 수 없다. 재실행 전에 VRAM 여유를 늘린 구성과 드라이버/CUDA 안정성을 점검해야 하며, 이 기록만으로 특정 드라이버 버전·전원·하드웨어 결함을 확정하지 않는다.

## 팀에 전달할 설명

> 기존 추천 정답을 유지하고 공개 자료에서 실제 성분 표기·사전 관측값 112건을 추가했습니다. 제품 성분을 효능 정답으로 바꾸거나 임의의 사용자 프로필을 만들지 않았습니다. 관련성 없는 자료와 불명확한 성분 이름을 제외하고, 미평가 값과 0을 구분했습니다. 출처와 고정 버전·사용 조건도 남겼습니다. Qwen3의 모델 교체 효과와 데이터 보강 효과를 따로 비교하고, 같은 개발 문항과 업데이트 예산을 사용합니다. 희소·복합 고민의 전문가 정답 확보와 새 사용자 시험은 여전히 남아 있습니다. 이전 검은 화면에 대응해 드라이버 오류가 새로 발생하면 해당 실험을 멈추는 감시를 추가했습니다.
