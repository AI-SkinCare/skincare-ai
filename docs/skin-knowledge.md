# 피부 자료 검색

앱 홈에서 **피부 자료 검색**을 열고 관리 안내, 연구 문헌, 제품 라벨 중 하나를 선택한다. 사진이나 설문 제출 없이 질문만으로 자료를 찾을 수 있다. 검색어와 개인의 사진·설문·분석 이력은 자료 DB에 저장하지 않는다.

| 검색 범위 | 자료와 제공 방식 |
|---|---|
| 관리 안내 | 국내 식품의약품안전처, WHO, 미국피부과학회, 미국 FDA와 기존 성분 연구의 한국어 요약을 검색한다. 피부 기록의 점수 계산은 앱 코드에 연결한다. |
| 연구 문헌 | PubMed에서 질환·성분별 14가지 검색식을 실행해 임상시험과 체계적 문헌고찰의 제목, 학술지, 발행일, 연구 유형, PMID를 수집한다. 제목을 누르면 연구 대상과 결과를 원문에서 확인할 수 있다. |
| 제품 라벨 | 미국 openFDA에 제출된 산화아연·이산화티타늄 함유 일반의약품 자외선차단 라벨과 제조사의 성분표 예시를 검색한다. 미국 라벨의 활성 성분만으로 개인 알레르기, 국내 제형 또는 구매 적합성을 판정할 수 없다. |

Spring은 사용자 인증 후 `POST /api/v1/knowledge/search`를 FastAPI의 `POST /knowledge/search`로 전달한다. 팀 서버 앞에 경로 허용 목록이 있다면 이 POST 경로에도 기존 내부 토큰 인증을 적용한다. 앱에는 내부 토큰이 들어가지 않는다.

```json
{"query":"아이 아토피 때문에 음식을 제한해야 할까요?", "kind":"guide"}
```

`kind`에는 `guide`, `research`, `label`을 쓴다. 검색어는 2~160자다. 응답의 `answerSourceId`는 실제 답변 문단의 `sources[].id`다. 문헌·제품 목록이나 답변 보류에서는 이 값이 비어 있다. `sources`에는 제목, 설명, 발행처, 원문 URL과 자료에 기록된 날짜가 있다. `asOf`는 DB 수집일이다.

SQLite FTS5가 한국어 검색어·성분 별칭·영문 제목으로 후보를 찾는다. 관리 안내에서는 서버의 Qwen2.5가 반환된 후보에서 질문에 답하는 문단을 고른다. 선택한 문단과 출처는 DB 원문대로 응답한다. 관련 문단이 질문에 답하지 못하면 답변을 보류한다. GPU가 바쁘거나 모델을 사용하지 않는 환경에서는 검색 순위와 자료 요약을 제공한다. 응답의 `origin`은 각각 `model_selected`, `no_match`, `retrieved`다. 이 검색 결과를 개인 성분 추천의 효능 근거로 자동 승인하지 않는다.

## DB 갱신과 검사

AI 저장소에서 다음을 실행한다. 기본 DB는 `configs/skin_knowledge.sqlite3`이며 서비스 요청 중 외부 API 연결은 필요하지 않다.

```powershell
python scripts/refresh_skin_knowledge.py
python -m pytest tests/test_skin_knowledge.py -q
```

한국어 안내만 수정했다면 `python scripts/refresh_skin_knowledge.py --local-only`로 기존 공개 데이터와 수집일을 유지하면서 다시 색인할 수 있다. 서버는 요청마다 읽기 전용 연결을 열어 교체된 DB를 바로 읽는다.

갱신 작업은 공개 API에서 문헌·라벨을 다시 수집하고, PMID와 라벨 세트 ID로 중복을 정리한다. 새 인덱스의 무결성 검사가 끝나야 기존 파일을 교체한다. 직접 확인한 한국어 요약과 검색 별칭은 `configs/knowledge_guides.json`, 기존 성분 출처는 `configs/ingredient_evidence.json`에서 관리한다. 이번 스냅샷은 전체 PubMed 문헌이나 국내 판매 화장품 전수 목록을 대표하지 않는다. 공개 수집 인터페이스는 [NCBI E-utilities](https://www.ncbi.nlm.nih.gov/books/NBK25501/)와 [openFDA 제품 라벨](https://open.fda.gov/apis/drug/label/)을 사용한다.

## 국내 대용량 자료

2026-11-24 팀 AI 서버에서 내려받은 국내 자료는 92,888건이다. 앱의 기존 세 가지 검색 범위에서 다음과 같이 사용한다.

| 앱 검색 범위 | 국내 자료 | 예시 질문과 결과 |
|---|---|---|
| 제품 라벨 | 원료 21,968건 | `가지열매추출물 영문명`으로 식약처 표준명, 영문명, 원본에 기재된 CAS 번호를 확인한다. [식약처 화장품 원료성분](https://nedrug.mfds.go.kr/pbp/CCBDE01) |
| 제품 라벨 | 심사 품목 20,920건 | `202603592`로 제품명, 업체, 심사번호, 심사일, 해당 품목 원문을 확인한다. 제품별 전성분과 개인별 효능은 이 목록의 제공 범위 밖이다. [식약처 기능성화장품 심사 품목](https://nedrug.mfds.go.kr/pbp/CCBDB01) |
| 관리 안내 | 식품 50,000건 | `얼큰낙지김치죽 나트륨`으로 식품명·기준량·함량·식품코드를 함께 확인한다. 이름이 모호하면 여러 제품을 표시한다. 포털 CSV에서 공개한 범위이며, 식품 섭취에 따른 피부 변화를 측정한 데이터는 포함하지 않는다. [전국통합식품영양성분정보표준데이터](https://www.data.go.kr/data/15100064/standard.do) |

기본 DB에는 관리 안내 30건, 연구 문헌 332건, 기존 제품 라벨·성분표 187건이 있다. 두 DB를 함께 사용할 때 총 93,437건이다. 문헌은 14개 검색식에서 각 60건까지 조회하고 PMID 기준으로 중복을 제거한다. 철회 논문, 동물 단독으로 색인된 연구, 제목에 특정 실험동물이나 반려동물 용어가 있는 연구를 제외한다. 각 논문의 연구 대상과 적용 범위는 원문에서 확인한다. 운동 후 세안, 면도, 수영장 이용, 화장 도구 세척 등 관리 안내에는 한국어 요약과 원문 링크가 있다.

다른 PC에서 국내 공개 자료를 설치하거나 갱신할 때는 AI 저장소에서 다음을 실행한다. 서버는 완성된 `data/skin-reference.sqlite3`를 다음 검색 요청에서 읽는다. Excel을 처리하는 패키지는 수집할 때만 필요하다.

```powershell
python -m pip install "openpyxl>=3.1,<4"
python scripts/import_skin_catalog.py --download-mfds --download-nutrition
```

### 직접 받으면 추가할 수 있는 자료

[AI Hub 문제성 피부 메이크업 추천 데이터(71961)](https://aihub.or.kr/aihubdata/data/view.do?aihubDataSe=data&currMenu=115&dataSetSn=71961&topMenu=100)의 **다운로드**에서 로그인·이용 신청 후 라벨링 데이터 중 질의응답 JSON을 받는다. 제공기관이 안내하는 전체 규모는 질의응답 10,043쌍, 지식 데이터 9,377건이다. 서비스에 새로 들어가는 건수는 라벨에 제목이 기재된 고유 참고문헌의 개수다.

1. 라벨 압축을 풀어 `data/knowledge-inbox/makeup/` 아래에 JSON을 둔다. 하위 폴더도 읽는다. 필요한 파일에는 `Annotation_info`와 `Source_info1`이 있다.
2. `python scripts/import_skin_catalog.py`를 실행한다. 다른 데이터 폴더의 원본도 이때 다시 읽으므로 유지한다. 인증키를 입력하거나 파일명을 바꿀 필요는 없다.
3. 앱의 **연구 문헌**에서 자료 제목·저자 또는 `컨실러`, `논코메도제닉` 같은 주제어로 검색한다. `Source_info1`부터 `Source_info5`에 기재된 제목·저자·발행처·연도를 보존하고, 출처 문단에 실제 등장하는 피부 관리 주제어를 검색에 사용한다. 같은 문헌을 다른 문단에서 인용하면 주제어를 합친다. 링크는 AI Hub 데이터셋 설명으로 연결된다. 생성형 질의응답, 대상자 설문과 라벨의 약물 조언은 개인 추천의 근거로 사용하지 않는다.

수동으로 받은 공식 파일도 같은 명령으로 가져올 수 있다. 식약처 원료성분 엑셀은 `ingredients/`, 심사 품목 엑셀은 `reviewed-products/`, 전국통합식품영양성분 CSV는 `nutrition/`에 둔다. 이 폴더들은 모두 `data/knowledge-inbox/` 아래에 있다. 입력 파일과 국내 DB는 각 서버의 로컬 데이터 디렉터리에 보관한다. 중복 레코드는 한 번만 색인하고, 상충하는 값이나 잘못된 파일이 발견되면 오류를 표시하고 기존 검색 DB를 유지한다.
