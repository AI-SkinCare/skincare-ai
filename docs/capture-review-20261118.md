# 정면 촬영 모델 선택과 설문 비교

2026-11-18 멘토링 후속 실험. 앱의 기본 입력은 양쪽 볼이 보이는 정면 사진 한 장이다. 셀프 촬영과 다른 사람이 찍어 주는 촬영은 카메라 렌즈만 달라진다. 정면에 보이지 않는 두피·귀 뒤 등의 상태는 이 입력에서 평가하기 어렵다.

후속 검증에서 이전 평가에 쓰이지 않은 공개 임상 정면 사진 10장과 사진·증상이 짝지어진 SCIN 사례 11건을 별도로 시험했다. [실제 정면 사진과 증상 설문 후속 검증](frontal-symptoms-followup.md)

## 같은 사진을 네 서비스 분류기로 판독한 결과

로컬 AI Hub 분할 기록에서 `origin_split=Validation`과 `split=holdout`을 모두 만족하는 **1,200장 전수**를 사용했다. 정면과 측면이 각각 600장이다. 공개 증례 사진은 앞선 연구에서 이미 관찰한 44장, 23개 환자·증례 그룹이다. 건선 20장, 아토피 18장, 지루 6장이며 얼굴과 몸, 발, 두피 등이 섞여 있다. 두 자료의 점수는 따로 집계했다.

| 분류기 | 합성 정면 정답/600 | 합성 측면 정답/600 | 합성 전체 정답/1,200 | 외부 정답/44 | 분류 중앙값 / P95 | 전체 파라미터 |
|---|---:|---:|---:|---:|---:|---:|
| DenseNet121 S2 (서비스) | 553 (92.2%) | 597 | 1,150 | 11 | 34.1 / 49.8 ms | 6,960,006 |
| 학습 DenseNet121 | 462 (77.0%) | 598 | 1,060 | 14 | 45.7 / 77.7 ms | 6,960,006 |
| EfficientNet-B0 | 447 (74.5%) | 596 | 1,043 | 13 | 23.7 / 40.8 ms | 4,015,234 |
| DINOv2-small 동결 + 선형 분류기 | 398 (66.3%) | 579 | 977 | 22 | 54.9 / 78.4 ms | 22,061,190 |

각 서비스 어댑터의 체크포인트와 자체 전처리를 그대로 사용했다. 라벨은 예측 후 채점에만 썼다. CPU 4스레드, 단건 호출, 워밍업 후 이미지 디코딩부터 예측 반환까지 측정했다. ZIP 읽기·서버 왕복·Grad-CAM·추천 생성은 분류 시간에 포함하지 않았다. DINOv2에서 학습된 파라미터는 선형 분류기의 4,614개다.

**서비스 선택은 S2 정면 촬영을 유지한다.** 합성 정면에서 가장 많이 맞혔고 네 후보 모두 이 PC에서 분류 자체는 빨랐다. S2 원본은 별도의 8:1:1 분할로 학습됐다. 해당 체크포인트의 학습 ID 전체가 없어 이번 1,200장과의 중복 여부를 입증할 수 없다. 이 표는 현재의 입력 조건에서 관찰한 결과다. S2를 독립 테스트에서 우승한 모델로 제시하기에는 자료가 부족하다.

| 분류기 | 외부 건선 정답/20 | 외부 아토피 정답/18 | 외부 지루 정답/6 | 외부에서 정면 얼굴로 표시된 사진 정답/6 |
|---|---:|---:|---:|---:|
| DenseNet121 S2 | 4 | 7 | 0 | 2 |
| 학습 DenseNet121 | 4 | 10 | 0 | 3 |
| EfficientNet-B0 | 4 | 8 | 1 | 2 |
| DINOv2 동결 | 17 | 5 | 0 | 3 |

외부 전체에서 DINOv2의 높은 점수는 건선에 집중된다. 지루 사진은 네 모델 중 세 모델이 한 장도 맞히지 못했다. 이 결과로 실제 정면 사용자나 일반 인구에서의 정확도를 추정하기 어렵다. 병원이나 팀원이 제시한 추가 사진은 사용 권한, 진단 라벨의 출처, 촬영 부위, 환자 단위 중복을 확인한 뒤 별도로 비교한다. 라벨 없는 시연 사진은 촬영·응답 확인에만 쓴다. 멘토링에서 언급된 팀원의 파인튜닝 DINO·피부 특화 모델은 가중치와 전처리 정보가 확보되면 같은 표에 추가한다.

앱 연동 시험에서는 두 색으로 된 도형에도 S2가 정상 분류 점수 97%를 반환했다. 분류 점수 임계값만으로 얼굴 입력을 보장하기 어렵다. Android와 iOS는 전송하기 전에 기기에서 단색 여부와 얼굴 수·크기를 확인하고, 조건에 맞지 않으면 재촬영을 안내한다. 이 검사는 모바일 입력 단계에 적용한다. 위 정확도는 기기별 얼굴 검출을 거치기 전 분류기의 수치다.

## 선택 설문을 바꾼 실제 추천 응답

동일한 가상 정상 분류(점수 0.90)와 가상 여성·30대 응답을 고정하고 로컬 FastAPI에 세 번 요청했다. 각 조건은 한 번만 실행했다.

| 변경한 입력 | 추천 상태 | 반환 성분 | 출처 | 요청 시간 |
|---|---|---|---|---:|
| 필수 설문만 | no_concern | 없음 | not_generated | 0.11초 |
| 자가 고민에 건조 추가 | generated | 글리세린, 세라마이드 | model | 9.93초 |
| 건조 + 회피 성분에 글리세린 추가 | generated | 세라마이드 | model | 8.31초 |

이는 자가 고민이 추천 생성을 시작하고 회피 조건이 반환 성분에 반영된 사례다. 추천 제품의 효능이나 피부 진단 정확도 상승을 측정한 실험은 아니다. 증상 설문(가려움, 각질, 반복 붉은기, 면포, 시작 시점, 부위)은 현재 분석별로 수집한다. 분류기에 추가했을 때의 개선 폭은 동일 사진·동시점 설문·검토된 라벨이 짝지어진 자료를 확보한 뒤 환자별 분리로 측정해야 한다.

## 휴대폰 화면까지 확인한 경로

Android 15 에뮬레이터에서 임시 계정으로 로그인하고 가상 인물 한 장과 가상 설문을 Spring에 보냈다. 실제 FastAPI 응답에서 최고 점수 라벨은 정상, 표시 점수는 41%였다. 앱은 분류 불확실 안내와 Grad-CAM을 표시하고 추천을 보류했으며 이력에서 같은 결과를 조회했다. 이 시연 사진에는 질환 정답이 없다. 위의 설문 비교 세 건은 별도로 분류 입력을 고정하여 실행했다.

Android 기기 테스트 5개가 통과했다. 전·후면 가상 카메라 JPEG, HTTPS 서버 주소, 추천 미생성 차단, 실연동을 확인했다. 실연동 안에서 단색·얼굴 없는 도형·두 얼굴 입력도 거부했다. Spring 단위 159개, PostgreSQL 통합 93개, Linux Swift 계약 테스트 29개가 통과했다. iOS 촬영·Vision 변경은 Swift 구문을 확인했으며 Xcode 빌드와 실기기 촬영 검증은 남아 있다.

## 분류 비교 재현

```powershell
python scripts/benchmark_capture_models.py --assets ../AI --out ../verification/capture-metrics-new.json
```

출력에는 모델별 정답 수, 각도·클래스별 집계, 불확실 건수, 지연만 기록한다. 스크립트는 원본 사진을 ZIP에서 메모리로 읽는다. 실제 얼굴 사진과 가중치는 팀 코드 저장소에 추가하지 않는다.
