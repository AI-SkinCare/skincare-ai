## 전문가에게 전달할 검토 자료

`claim_review_queue.jsonl`에는 각 원본 사례의 입력, 원래 추천 문장, 출처, 조회 결과, 격리 사유가 같이 있다. 다음 항목을 사례별로 기록한다.

1. 주장에 나오는 성분과 문헌의 연구 성분이 같은가? 식물 종·부위·제형도 확인한다.
2. 대상이 사람인지 동물/세포인지, 결과가 현재 주장과 관련 있는지 확인한다.
3. 문헌의 농도·기간·사용 조건을 원래 설명이 과장하거나 임의로 확장하지 않았는지 확인한다.
4. 여러 고민을 함께 가진 사용자의 모든 고민을 다뤘는지, 입력에 없는 원인을 단정했는지 확인한다.
5. 승인, 수정 후 승인, 보류/제외 중 하나를 선택하고 검토자·근거 URL·검토 날짜를 남긴다.

희소·복합 고민 후보는 `rare_multi_review_candidates.jsonl`에 있다. 희소 고민 원본 후보는 과각질 60건, 홍조 140건, 탄력 저하 49건, 민감성 9건이다. 이는 원본의 유지/격리 사례를 합쳐 재검토하도록 모은 수이며 새로운 학습 사례가 아니다. 복합 고민 원본 후보는 1,556건이다.

GPU 비교가 끝나면 `model_content_review.jsonl`에 개발 문항의 모델별 답변을 나란히 모은다. 내용 검토에는 전체 고민 충족, 근거 일치, 입력에 맞는 설명, 사용법 적절성의 네 항목을 기록한다. 기존 단일 고민 정답과 문구가 비슷하다는 이유만으로 내용에 만점을 주지 않는다.

## 새 사례 수집과 독립 시험

`external_case_template.json`을 복사해 **실제로 신규 수집한** 사례를 작성한다. 성별·나이·피부타입·모든 고민을 입력하고, 각 고민마다 허용 성분 목록과 근거 URL, 설명을 전문가가 작성한다. 수집 배치 ID와 검토자 식별자·전문 분야·날짜를 남긴다. 검토 전에는 `review.status=pending`, `claim_evidence_verified=false`를 유지한다.

현재 수집 목표는 각 고민을 포함한 신규 사례 20건 이상, 복합 고민 40건 이상이다. 이것은 최소 수집 목표이며 통계적 성능 보증은 아니다. 복합 사례가 각 고민의 건수에 포함되므로 합계를 독립 표본 수로 해석하지 않는다. 검토자 정보와 신규 수집 여부는 수집 팀의 선언이며 프로그램이 자격이나 실제 수집을 인증하지 않는다.

검증 코드는 모든 과거 원본 학습/검증 입력과 같은 프로필을 차단하고, 중복 ID·중복 입력·미승인 정답·일부 고민의 정답 누락·분포 부족을 거부한다. 서로 다른 성분이 유효한 대안일 수 있으므로 허용 성분 집합을 고민별로 작성한다.

합성 진단 입력 120건은 8종 단일 고민×4종 피부타입×2종 성별 64건과 모든 고민 쌍×2종 프로필 56건이다. 형식/내용 검토 준비에만 사용하며 전문가 정답도 실제 새 사용자도 아니다. 독립 시험 건수는 현재 **0건**이다.

개발 데이터로 모델 선택을 끝낸 다음에만 외부 시험을 실행한다. 외부 사례와 선택한 어댑터의 해시를 봉인하며, 모델·사례가 바뀌면 기존 봉인에 덮어쓰지 않는다. 외부 자동 성분 점수는 검토된 참조 어휘에서 인식한 이름만 측정한다. 미등록 성분이나 주장·사용법·전체 고민 충족은 사람이 확인해야 하므로 일반적인 추천 정확도로 제시하지 않는다. 모델 폴백 답은 모델 단독 점수에 섞지 않는다.

## 실행과 상태 확인

AI 레포 루트의 기존 가상환경을 사용한다.

```powershell
# 빈출 출처 조회 범위를 늘리거나 캐시에서 검토 목록 재생성
.\.venv\Scripts\python.exe -m src.llm.review_evidence --resolve 200
.\.venv\Scripts\python.exe -m src.llm.prepare_followup_review --download-dictionary --download-cosing

# 현재 실행한 순차 실험. 실행 중인 동일 실험을 중복 실행하면 OS 잠금으로 차단
.\.venv\Scripts\python.exe scripts/run_quality_followup.py
# 중단 후, 동일 코드/설정에서만 완료 단계를 건너뛰고 이어서 실행
.\.venv\Scripts\python.exe scripts/run_quality_followup.py --resume

# 실제 신규 사례를 모은 뒤, 모델 선택을 끝낸 상태에서 우선 수집·검토 조건 검사
.\.venv\Scripts\python.exe -m src.llm.evaluate_external_cases --cases data/new_human_cases.jsonl --adapter outputs/rec_sllm_v3/adapter --validate-only
# 검사 통과 뒤 --validate-only를 제거하면 선택한 모델로 외부 시험 수행
```

단계 상태: `outputs/quality_followup_20261006/status.json`. 로그·개발 결과·비교표는 같은 폴더의 단계별 `.log`와 `val_eval/`에 있다. 종료 코드 0, 동일 데이터/문항, 어댑터 파일과 학습 데이터 ID를 확인한 단계만 완료로 기록한다. 실패한 단계 뒤로는 진행하지 않는다. 코드/설정이 변경되면 같은 실험의 이어서 실행을 거부한다. `src/llm` 코드는 현재 실험이 끝날 때까지 수정하지 않는다.

2026-10-06 검증: **pytest 94개 통과**, v3 전체 8,233행 무결성 검사 통과. GPU 순차 실험을 시작했고 규칙 기준선과 무결성 단계가 완료됐으며 원본 모델 평가가 실제 문항을 처리하는 것을 확인했다. 완료·실패 때 알려주는 시간당 모니터를 설정했다. 최종 모델 비교 성능은 아직 나오지 않았다.

기존 Qwen3 실험은 체크포인트 170까지 존재하지만 최종 어댑터가 없어 완료 실험으로 취급하지 않았다. 이번 실행은 기존 Qwen2.5 v2와 별도 v3를 비교하며 그 Qwen3 실험을 덮어쓰지 않는다.

### 2026-10-07 학습 중단과 재개
